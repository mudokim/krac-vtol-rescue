# Handoff - 2026-07-06

## 현재 상태

이 브랜치(`fix/repro-run`)는 PX4 SITL + Gazebo + MAVROS 기반 VTOL 구조 미션을 기존 FSM 중심 실행에서 BehaviorTree 중심 실행으로 옮긴 상태다. 핵심 경로는 `krac_control`의 `krac_bt_runner`이며, krac24의 precision landing 흐름을 BT action/condition으로 이식했다.

2026-07-06 기준으로 `gz_standard_vtol`에서는 전체 BT 미션이 성공으로 끝나는 것을 확인했다. 검증 범위는 real mission upload, rescue 지점 precision landing, gripper close topic publish, return leg resume, final precision landing, `AUTO.LAND`, disarm까지다. 자세한 검증 기록은 `docs/standard_vtol_bt_gripper_full_validation_2026-07-06.md`에 있다.

## 핵심 변경

- `krac_control`에 BehaviorTree.CPP 기반 runner 추가
  - `krac_bt_runner`
  - `krac_bt_mock_runner`
  - `precision_lander`
  - BT action/condition 구현: `ros2_ws/src/krac_control/src/bt_*.cpp`
  - BT XML: `ros2_ws/src/krac_control/bt/krac_mission_bt_robust.xml`
- krac24 precision landing 흐름 이식
  - `/vision/target_error` 구독
  - `/precision_lander/enable` 서비스
  - `/precision_lander/cmd_vel`을 MAVROS velocity setpoint로 relay
- gripper topic 기반 action 추가
  - `OpenGripper`
  - `CloseGripper`
  - Gazebo servo bridge topic: `/model/<model_name>/servo_4`, `/servo_5`, `/servo_6`
- `way3.plan`을 BT intervention 방식에 맞게 정리
  - rescue intervention: seq 1
  - resume after rescue: seq 2
  - final landing intervention: seq 7
  - drop leg는 실제 waypoint가 없어 BT main path에서 제외
- `krac_vision`에 BT용 vision launch 추가
  - `vision_tracker.py`
  - `vision_bt.launch.py`
  - `scripts/run_vision_bt.sh`
- PX4/Gazebo asset 적용 스크립트 보강
  - standard VTOL gripper patch
  - AMSR VTOL camera/gripper/model asset
  - optional mission object model copy 경로 보강
- 디버그 실행/로그 수집 스크립트 추가
  - `scripts/run_sitl_bt.sh`
  - `scripts/run_bt_debug.sh`
  - `scripts/collect_bt_debug_logs.sh`

## 실행 순서

일반 BT SITL 실행:

```bash
cd ~/vtol-aam-rescue
source /opt/ros/humble/setup.bash
source ros2_ws/install/setup.bash
./scripts/run_sitl_bt.sh
```

디버그 로그까지 수집하는 실행:

```bash
cd ~/vtol-aam-rescue
source /opt/ros/humble/setup.bash
source ros2_ws/install/setup.bash
timeout 360 scripts/run_bt_debug.sh
```

기본값은 다음과 같다.

- `VEHICLE_MODEL=gz_standard_vtol`
- `GZ_MODEL_NAME=standard_vtol_0`
- `APPLY_PX4_ASSETS=true`
- `START_AUTO_SPAWN=true`
- `START_IMAGE_REPUBLISHER=true`
- `START_VISION_BT=true`
- `MISSION_UPLOAD_STUB_SUCCESS=false`
- `GRIPPER_STUB_SUCCESS=false`

AMSR 모델로 실행할 경우 최소한 다음 환경 변수를 맞춰야 한다.

```bash
VEHICLE_MODEL=gz_amsr_vtol GZ_MODEL_NAME=amsr_vtol_0 ./scripts/run_sitl_bt.sh
```

## 아직 남은 일

- real YOLO 기반 full mission은 아직 최종 검증 전이다. 현재 full mission 성공은 simulated `/vision/target_error` 기준이다.
- drop leg는 실제 drop-zone waypoint/seq가 없어 `MissionSequence`에서 제외되어 있다. waypoint가 확정되면 `CruiseToDrop`, `DropOperation`, `ResumeAfterDrop`을 다시 연결해야 한다.
- AMSR 커스텀 기체는 asset/model 경로와 gripper mesh/patched SDF를 넣어둔 상태지만, 최종 full mission 검증 기준은 아직 `gz_standard_vtol`이다.
- `ros2_ws/src/bt.xml`은 오래된 draft로 보이며 현재 launch에서 참조하지 않는다. 필요 없으면 삭제 후보다.
- `krac_vision/weights/best.pt`는 `.gitignore`의 `*.pt` 규칙 때문에 Git에 포함되지 않는다. real YOLO 실행 환경에서는 별도 전달이 필요하다.
